RealityWarden Desktop Support

Offline guide · Public Alpha · REAL-device first

Start with the reviewed REAL rig

The current executable product scope is exactly ESP32-S3 + SG90 + HC-SR04. SG90 signal uses GPIO18; HC-SR04 uses TRIG GPIO5 and ECHO GPIO4. The 5V ECHO signal must pass through a 5V→3.3V divider before GPIO4. Other boards, pins, and sensor configurations are not silently substituted.

  1. Plug in the rig and choose Auto-detect in the REAL HARDWARE task rail.
  2. Existing RealityWarden firmware is diagnosed before connection. A listed blank or unresponsive ESP32-S3 can instead enter Prepare first flash.
  3. Review the exact port, image version, and SHA-256, then explicitly confirm. Only the paired reviewed image or a valid write order is accepted.

Recover from startup

  1. Use Retry startup in the recovery window.
  2. If retry fails, use Copy details, then export diagnostics from File → Export Local Diagnostics….
  3. Restart RealityWarden. Uninstall/reinstall preserves user data by default.

An unavailable local LLM does not block startup. Supported commands fall back explicitly to the local rule compiler.

Recover a project

  • Open a .openreality.json file with File → Open Project.
  • Use File → Restore for the last validated autosave.
  • Corrupt autosaves are quarantined and never silently replace the current workspace.

Local diagnostics and privacy

The JSON bundle is created only after you choose a destination. RealityWarden does not upload it.

It contains runtime/version metadata plus a bounded, allowlisted, redacted startup-log excerpt. It excludes projects, imported assets, prompts, generated commands, audit evidence, hardware results, serial ports, environment variables, and credentials. Review it before sharing.

REAL HARDWARE boundary

The matching official build verifies a version-, profile-, and digest-bound REAL release approval locally. A missing or altered approval keeps execution locked; arbitrary JSON files and packaged environment variables cannot unlock it. Every actuation still requires explicit operator confirmation, fresh sensor evidence, and the full safety gate. Missing, stale, invalid, or frozen evidence blocks execution. A software acknowledgement is never presented as proof of physical motion, and the SG90's commanded angle is open-loop rather than a measured position.

What SIM LAB is for

SIM LAB is an explicit, secondary, zero-signal tool for testing proposal parsing, rules, actions, and audit presentation without touching hardware. It does not prove the real environment safe and never replaces a failed REAL operation.

Third-party notices

Use Help → Third-Party Notices to open the packaged production dependency inventory, redistributed model attributions, and included license texts. It works offline.

Public Alpha boundary

The reviewed reference rig is the only current REAL execution target. Simulation profiles are available only inside SIM LAB; unfinished device families cannot be used as real-device or release evidence.
