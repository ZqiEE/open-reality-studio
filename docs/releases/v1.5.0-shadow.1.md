# RLSOK v1.5.0-shadow.1 — composable local Shadow evaluation

This prerelease makes the composable ROS 2 Shadow work available as an
installable, self-contained Linux x86_64 evaluation package. The existing
stable runtime/Cloud installation remains v1.4.5 / product v1.3.0.

- Reuses the trajectory, absolute Cartesian and allowlisted TP program
  adapters, recursive interface hashes, all-declared-path coverage and
  controller/tool/frame/calibration/URDF/bridge bindings.
- Adds read-only local controller-export fingerprinting over selected IDs and
  complete parameter objects; preserves original observation timestamps.
- Exports per-path assessments and a hash-verification command, making the
  exact calibration failure reviewable alongside standard Evidence.
- Creates observation output atomically without replacing earlier Evidence.
- Includes four generated schemas, intake/export templates, integration docs,
  the optional source Humble kit, and a complete installation-to-Evidence guide.
- Packages on the host without running target binaries, ROS, local tests or
  GitHub Actions. The pinned Linux Node archive is checksum-verified. Source
  archives, distribution manifests, SHA-256 files and dependency inventory
  accompany the release. The evaluation installer requires no sudo and writes
  only a new versioned directory.

Start at [the customer self-service guide](https://github.com/realitywarden/rlsok/blob/v1.5.0-shadow.1/docs/fanuc-shadow-self-service.md).
The package's `BUILD-MANIFEST.json` identifies the exact source and validation
scope. Its launcher permits only local profile commands and Evidence checks.

No database migration or Cloud deployment is required. Existing profiles keep
schema version 1; new `.assessment.json` output is additive. No production
Permit or authenticated approval is introduced. All profile evaluation data
stays local; Hosted reference/artefact storage is described separately.

**Not validated:** installation/upgrade, exact-release local regression,
Ubuntu 22.04/Humble execution, customer private interfaces, actual FANUC
configuration exports, physical robots and customer acceptance. Absolute
Cartesian support requires the customer's actual action definition, goal,
units and semantics; the public relative JogCartesian contract is not a
substitute. This is not certified functional-safety software.
