## 2. 硬约束：conformance 对 page.tsx 做字符串切片断言（改前必读）

`lib/conformance/runConformance.js` 直接读 `app/page.tsx` 源码做断言，拆分**不能**破坏它们：

- L172：`page.slice(indexOf('function CommandDock('), indexOf('function WorkspaceDeviceStrip('))`
  —— **`CommandDock` 与 `WorkspaceDeviceStrip` 必须仍以 `function X(` 形式留在 page.tsx，且前者在后者之前**。
- L198：`uiSource = page + labConfigurator + auditPanel` —— 断言跨这三处源码。
- L223–224：`page` 含 `SIMULATION · REAL MIRROR SEPARATE`、`[SIMULATION]`、
  `no signals were sent to real hardware`（**Invariant 6 可见区分，不可移除仿真标记**）。
- L283：`page` 含 `<RealDeviceWorkspace` 且 `<RealHardwarePanel`。
- L289–293：`page` 含 `open_reality_lab_workspace`、`open_reality_adapter_execution_package`、
  `adapter_target_id`、`workspace_devices`、`deployment_readiness`。

**规则**：把逻辑/子视图外提到 `components/` 时，凡被上述断言点名的字符串/函数，要么保留在
page.tsx，要么**同步更新 conformance 断言到新文件**（AGENTS 允许"设计变更同步更新断言，
但保护必须等价或更强，并在提交信息说明"）。每拆一块就地跑 `npm run test:conformance`。

## 3. 目标首屏结构：意图 → 门 → 结果 + 回执

三段式主轴（REAL 模式默认），把现有零散信息重排到三个语义槽：

1. **意图（Intent）** — 收敛到 `CommandDock`：命令输入 + 单一 Run 控件 + 单一状态徽章。
   消除 B2（顶栏与终端两套 Run/Stop，留终端一套）；顶栏只留状态与导出。
2. **门（Gate）** — 单一权威运行状态条，展示管线 `compiled → gated → executed|BLOCKED`。
   落 B1 长期方案：一个 run-state 源，其余位置只订阅；四词表统一为一套带前缀的词表。
   **BLOCKED 用正向视觉**（非红色报错样式）：一枚"已拦截 / Refused"状态卡，写清
   **拦了什么、为什么、下一步**，旁边直接给"导出回执"入口——把拒绝呈现为产品的英雄时刻。
3. **结果 + 回执（Result + Receipt）** — `AuditPanel` 升为右栏首要位置（B/C3：EXECUTED 后
   用户最想看的审计时间线目前埋在 Inspector 深处）；顶部固定"导出审计回执（JSON+MD+HTML）"。
   REAL 侧诚实入账（`attempted_unconfirmed` 不伪造）、SIM 侧 `[SIMULATION]` 标记保持。

SIM LAB：`workspaceMode==='simulation'` 时明确的次级蓝色区,入口在 AppHeader;进入即断开 REAL、
清 REAL 遥测（已实现）；文案强调"零信号、非回退、不证明物理安全"。**不删,仅确保视觉从属。**

## 5. 建议执行顺序（每步一个功能单元、可独立验证/提交）

1. **单一权威运行状态源**（B1 长期）：建 run-state，`CommandDock`/顶栏/右栏改为订阅；
   删除重复 Run/Stop（B2）。→ 跑 conformance/desktop。
2. **门段正向化**：BLOCKED 状态卡（拦什么/为什么/下一步 + 导出回执入口），去红色报错样式。
3. **回执前置**：右栏 AuditPanel 升首位 + 固定导出条；Governor/Inspector 改 tab（C3）。
4. **布局壳外提**：`PrimaryWorkspaceLayout` + `RunStateBar` 抽出，`Home` 瘦身；同步任何被
   影响的 conformance 断言（若把点名字符串移出 page.tsx，则改断言指向新文件并说明）。
5. **顶栏收敛**：文件操作进原生菜单，顶栏留 Run+导出（C4）。
6. **出口验收自动化**：新增/补一条 e2e，跑通"受治理命令 → 触发一次拒绝 → 导出回执"，
   接入 fast 快速门（对齐 v0.6 出口标准）。

## 6. 验证与执行环境（重要）

- 每一步后跑不产临时目录的字符串断言门禁：`npm run test:conformance`、`node lib/desktop/runDesktopTests.js`。
- **完整 `npm run verify` 必须在 Windows 本机跑**：`build` 清理脚本依赖 PowerShell；且当前
  云端 Linux 桥接**禁 unlink**，`tsc→临时目录`型测试（real-hardware/virtual-loopback 等 tsc-to-tmp）
  清不掉临时目录。→ 结论：**这类 page.tsx 改动更适合在"在你电脑上"跑 Cowork 任务执行**
  （桌面端能原生跑 build + 46/48 真机安全测试 + 5/5 虚拟回环），或改后由你在本机跑一遍 verify 拿全绿。
- 提交按功能单元，message 写明验证结果；push 由所有者本机负责（AGENTS）。

## 7. 关于"要不要删一真一虚"（已定论，记录在此）

**不删。** 双模是定位本身要求：SIM LAB 是 `POSITIONING.md` 明确保留的"零信号次级模式"，
且 **Invariant 6"仿真与真实可见区分"需要仿真存在才成立**（conformance L224 断言 `[SIMULATION]`
标记）。删 SIM 会连带删掉 `virtualLoopbackAcceptance.test.ts`（5/5 安全证据链）、runnable paths、
手册 simulation-only 资产、marketplace simulation-only 语义——整片已接入门禁的测试全塌。
"显得像玩具"的担忧靠**把仿真降级为显式次级 + 首屏让门/回执领衔**解决,而非删除。
